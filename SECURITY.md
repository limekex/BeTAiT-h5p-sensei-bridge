# Security Policy

## Reporting a Vulnerability
If you discover a security vulnerability, please do not create a public issue.
Contact the maintainer through an existing private channel with steps to reproduce, the deployed commit/package checksum and dependency versions. Do not include learner records or raw xAPI statements in a public issue.

A public private-reporting channel is not configured yet: GitHub private vulnerability reporting was disabled when checked on 2026-11-03. Enabling and verifying that channel, or publishing a monitored security email address, is a prerequisite for public release. No response-time guarantee is currently published.

## Supported Versions
`1.2.0-dev` is an unreleased stabilization candidate. The historical `v1.0.0` release is not evidence that current security fixes are installed. Maintainers must identify the deployed commit and validate upgrades against the documented staging gate. A stable-version support/backport policy must be published with the first verified release.
